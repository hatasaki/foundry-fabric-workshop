# 講師ガイド — Fabric IQ × Foundry IQ × Foundry エージェント

[ワークショップトップ](../../README.md) · [English](../en/README.md)

**標準180分、発展込み240分。** [開催準備](preparation.md)で、講師が研修リソース、受講者アカウント、組み込みロールを設定します。[受講者ガイド](../../student/jp/README.md)は別に配布します。

## 開催前の確認

本番の受講者とは別の名前と空のワークスペースを使い、受講者相当の2アカウントで以下を順に確認します。継承ロールやグループを含む **アクセス制御 (IAM) → アクセスの確認** で、広い権限がないことを確かめます。

1. **Lab 00：** Azure ポータルで指定された親リソースの概要を開き、自分の子プロジェクトを新規作成できる。既存の Foundry プロジェクトには入らない。
2. **Lab 01〜03：** 自分の空の Fabric ワークスペースでレイクハウス、ノートブック、受講者別の `studentN_mfg_ontology` を作成し、構成案を適用できる。
3. **Lab 04：** 事前に下表の権限設定を済ませる。受講者相当のアカウントで本人のプロジェクトを開き、接続先一覧から共通 Search を選べること、プロジェクトのマネージド ID で接続でき、8文書を直接登録できることを確認する。
4. **Lab 05〜06：** 同じ親 Foundry リソースの2つの子プロジェクトで、親の `Foundry Project Manager` を再付与せずに、各自が **OneLake カタログ** から自分のオントロジーに別々の接続名で接続できる。各接続のエンドポイントが本人のアイテム ID を指し、指定モデルと自分のナレッジ ベースをエージェントに設定して保存できる。本番前の検証では、受講者の接続作成用ロールを外した状態でも個別照会と統合メモが動くことを確認する。クラス規模に対する索引数、モデルクォータ、埋め込みスループット、RBAC の反映時間も確認する。

同じ権限で通らない操作は、どの ID・スコープ・操作が拒否されたかを確認します。受講者に `Owner` やリソースグループの `Contributor` を付与して回避しません。

## 当日の進行

| 区間 | 講師が行うこと |
| --- | --- |
| Lab 00 の開始前 | 研修用の親 Foundry リソースに一時 `Foundry Project Manager` を付与し、Azure ポータルの親リソースの概要へのリンクを配布します。受講者は自分でプロジェクトを作成します。 |
| Lab 00 の直後から Lab 01〜03 | `studentN` と本人を照合し、親の一時ロールを外します。本人の子プロジェクトに `Foundry User` と `Foundry Project Manager`、研修 Search に `Search Service Contributor` を設定します。プロジェクトのマネージド ID にも Foundry と Search のロールを設定し、Lab 04 までに反映を確認します。 |
| Lab 04 | 受講者が自分で Search に接続し、ナレッジ ベースの保存と8本の **準備完了** を確認して Lab 05 へ進みます。講師は権限エラーなど、受講者自身で解消できない問題に対処します。 |
| Lab 05 | 親の権限は追加しません。Fabric IQ は本人の OAuth、Foundry IQ はプロジェクトのマネージド ID を使います。両接続とエージェントの保存を確認後、受講者の子プロジェクトの `Foundry Project Manager` と研修 Search の `Search Service Contributor` を外します。 |
| Lab 05 の個別テスト〜Lab 06 | 受講者はエージェントの保存後、そのまま個別テストを実施します。ロールの撤回完了の通知は不要です。グラフのロード待ちが長い場合はグラフだけ別記録にし、後半へ進みます。 |

権限の反映に時間がかかる場合は、Lab 04 の開始を遅らせます。Lab 00 のプロジェクト作成を省略したり、講師が代行したりしません。

## 合格基準

| 確認 | 合格条件 |
| --- | --- |
| Fabric の取り込み・モデル | 15テーブル。ERP初期リストは2受注・8,050万円。プラン → 実行 で13エンティティと16リレーションが保存され、別々の `erp#Order` と `mes#Order` が関係と未反映リスクのルールで結び付く。 |
| Fabric IQ の照会 | `SO-2026-004`、`SO-2026-009`、`SO-2026-015`。3受注・9,970万円、潜在違約金235万円/日。`SO-2026-015` は ERP 2、対応する `WO-2026-1019` は MES 30、良品15／受注40のためERP未反映。 |
| Foundry IQ の文書検索 | 個別接続、File ソースの8ファイル、ナレッジベースが揃う。個別の文書質問で `knowledge_base_retrieve` が成功し、決裁規程とSLAを引用する。 |
| 統合判断 | 同じ **応答** で `ask_ontology` と `knowledge_base_retrieve` が成功し、両出力を判断メモに使う。9,970万円（受注額）を9,000万円（決裁基準）に当てはめ、COO決裁とする。日次違約金を受注額に足さない。 |
| 品質・報告 | 対象ワークを隔離する。182 ppmのロットを175 ppm超の規程と照合して返品対象とし、認定された代替候補を示す。初動8Dは `CUS-001`／`002` が検知後48時間、`CUS-003` がMESの品質保留記録から24時間。単独質問でも、記録時刻がないため正確な締切日時は算定しない。 |
| グラフ（別記録） | 11エンティティ型を投影し、つながりを可視化する。データロードと実際のクエリ実行を別々に記録する。GQLは発展課題。 |

[元データの照合値](../resources/expected_oracle.json)は講師用です。エージェントの指示、チャット、ナレッジソースへ入れません。応答の **トレース** からツールの入出力を確認します。ツール一覧、片側の照会、SQLだけの照合、講師デモは統合の合格に数えません。

## 当日の対処と終了

- **Fabric IQ の接続名の重複：** オントロジーを作り直さず、本人が Fabric で開いたオントロジーの画面上部の名前を選び、**名前** 欄を `studentN_mfg_ontology` に変更します。その名前で Lab 05 の接続をやり直します。他のプロジェクトの接続は削除せず、権限の追加で回避しません。
- `403`：受講者、プロジェクトのマネージド ID、Search のマネージド ID を区別して権限を確認します。埋め込みの `429` は表示された時間を待ち、失敗分だけ再試行します。必要なら登録の開始時刻をずらします。
- Fabric の作成画面が読み込み中のままの場合は、ワークスペース一覧で項目の作成有無を確かめます。同じ名前で続けて作成しません。
- 終了後、受講者へ付与した研修用ロールを撤回し、承認済みの保持期間に従って研修用アカウント、プロジェクト、ワークスペース、Search のソース・KB・索引を整理します。共用容量やモデルの停止・削除は、研修専用と確認できる場合だけ行います。
